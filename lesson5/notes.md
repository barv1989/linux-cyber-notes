# Lesson 5 — `sudo` и права администратора в Linux

## 1. Кто такой root и зачем `sudo`

- **root** — суперпользователь в Linux. Он может:
  - читать и менять любые файлы;
  - устанавливать и удалять программы;
  - менять системные настройки;
  - создавать и удалять пользователей.
- Работать под root **постоянно** опасно:
  - легко сломать систему одной командой;
  - выше риск запустить вредоносную команду.
- Поэтому обычные пользователи работают без прав root,
  а временный доступ получают через команду **`sudo`**.

**Идея:**  
> Работай как обычный пользователь, а `sudo` используй только тогда, когда это реально нужно.

---

## 2. Базовое использование `sudo`

### 2.1. Запуск одной команды с правами root

```bash
sudo command
```

Примеры:

```bash
sudo apt update
sudo apt install htop
sudo mkdir /opt/myapp
```

Что происходит:
- система спрашивает **пароль твоего пользователя**, а не пароль root;
- команда выполняется с правами root **только на время этой команды**.

---

### 2.2. `sudo -i` — открыть “root-оболочку”

```bash
sudo -i
```

- Открывает shell от имени root (приглашение обычно меняется с `$` на `#`).
- Все команды после этого идут с правами root, пока не выйдешь:

```bash
exit
```

---

### 2.3. Другие полезные варианты `sudo`

- Показать, какие `sudo` команды тебе разрешены:

  ```bash
  sudo -l
  ```

- Сбросить кэш пароля sudo и заставить систему снова спросить пароль:

  ```bash
  sudo -k
  ```

---

## 3. Файл `/etc/sudoers` и команда `visudo` (ТЕОРИЯ)

Настройки `sudo` хранятся в файле:

```bash
/etc/sudoers
```

**НЕЛЬЗЯ** редактировать этот файл обычным редактором (`nano /etc/sudoers`) —  
если сделать ошибку, `sudo` перестанет работать.

Используется команда:

```bash
sudo visudo
```

Она:
- открывает файл в безопасном режиме;
- проверяет синтаксис перед сохранением;
- не даст сохранить файл с ошибкой.

---

## 4. Безопасность и хорошие привычки

**1. Не запускай случайные команды с `sudo`, если не понимаешь, что они делают.**

**2. Не используй `sudo` для всего подряд.**

**3. Не работай долго под root через `sudo -i`.**

**4. Не передавай свой пароль никому.**

---

## 5. Мини-cheatsheet по `sudo`

```text
sudo command   # выполнить одну команду с правами root
sudo -i        # открыть shell от имени root
sudo -l        # показать, какие sudo-команды разрешены
sudo -k        # сбросить кэш пароля sudo
visudo         # безопасное редактирование sudoers
```

## 6.2. Grammar: have to / don’t have to

- **have to** = должен (по правилу)
- **don’t have to** = не обязательно

Примеры:

- You **have to** use sudo to install programs.
- You **don’t have to** use sudo for files in your home folder.
